# ILSC — Interface-Level Semantic Cohesion

Working repository for the ILSC metric. This package covers **Day 1–3 of the empirical track** (multi-source curation, the
field-availability study, the pair-level co-availability study) plus **Day 1–2
of the metric track** (parser and feature extraction), and the decisions that
came out of them.

Anyone starting from this folder can rebuild everything in about 25 minutes.

---

## 2. Reproducing everything

```bash
# 1. Dependencies
pip install -r requirements.txt
npm install                       # swagger2openapi 7.0.8, used by step (b) only

# 2. Fetch S1 — RAMA threshold benchmark (Bogner et al. 2020), the anchor
git clone --filter=blob:none --sparse \
    https://github.com/restful-ma/thresholds.git rama-thresholds
cd rama-thresholds
git sparse-checkout set benchmark-repository/openapi
git checkout 5b0b2a3322d3b2b7c0e0f2c0c0ad0e524e67bf82
cd ..

# 3. Fetch S2 — APIs.guru current snapshot
git clone --filter=blob:none --sparse \
    https://github.com/APIs-guru/openapi-directory.git openapi-directory
cd openapi-directory
git sparse-checkout set APIs
git checkout f04b8d0bcd39c52e1cf3ad7a5fe744709832ae49
cd ..

# 4. Run
python run_all.py
```

**Pinned commits:** S1 `5b0b2a3322d3b2b7c0e0f2c0c0ad0e524e67bf82` ·
S2 `f04b8d0bcd39c52e1cf3ad7a5fe744709832ae49`.
Without pinning, the corpora change under you and no result is reproducible.

Steps are individually runnable, and the expensive half of `filter.py` is
checkpointed, so a dedup rule can be re-evaluated without re-parsing 6,757
specs:

```bash
python src/filter.py --scan S1     # parse into .cache/  (~4 min)
python src/filter.py --scan S2     # ~6 min
python src/filter.py --merge       # dedup + write       (seconds)
```

Install libyaml (`yaml.CSafeLoader`) or the scan takes roughly ten times longer:

```python
import yaml; print(hasattr(yaml, "CSafeLoader"))
```

## 3. Corpus statistics

Two sources, 6,757 specification files in.

| Stage | Removed | Reason |
|---|---|---|
| a — parse | 49 | malformed file |
| a — structure | 184 | no `paths` or no `info` |
| b — RPC-shaped | 1 | every path identical |
| c — < 3 operations | 1,264 | too small for a pairwise metric |
| d — dedup (within source) | 1,199 | older version of the same API |
| e — dedup (cross-source) | 1,854 | already present in S1 |
| **Surviving** | **2,206** | |

**Composition of the survivors**

| Property | Value |
|---|---|
| S1 (RAMA) / S2 (APIs.guru) | 1,014 / 1,192 |
| OpenAPI 3.x | 2,062 (93.5%) |
| Swagger 2.0 | 144 (6.5%) |
| Operations per service | min 3, median 16, mean 44.4, max 11,422 |
| Total operations | 97,912 |
| Within-service pairs | 77,611,030 |
| Distinct providers | 616 |
| Admin endpoints stripped | 62 across 48 services |
| Strict validation (D-02, n=200) | **97.5% valid** — S1 100%, S2 94.9% |

> **The version split is an artefact, not a fact about the world.** RAMA
> converted its inputs to OpenAPI 3 upstream, so S1 is 100% 3.x by
> construction. S2 alone is 26.9% Swagger 2.0. Never read the pooled split as a
> statement about how authors publish (D-10).

**Provider concentration** — the largest threat to external validity, and it
differs sharply by source:

| | Services | Providers | AWS + Google + Azure |
|---|--:|--:|--:|
| S1 (RAMA) | 1,014 | 315 | **589 (58.1%)** |
| S2 (APIs.guru) | 1,192 | 460 | 444 (37.4%) |
| pooled | 2,206 | 616 | 1,033 (46.8%) |

S1 — the peer-reviewed anchor — is the *more* concentrated of the two. Reusing a
published corpus buys comparability with Bogner, **not** diversity; Sec. 7 of the
proposal currently implies both (D-12).

## 4. Open decisions

| # | Decision | Options | Blocks |
|---|---|---|---|
| D1 | Provider cap | none / 50 / 30 / 20 per provider | Exp. 1 |
| D2 | Oversized services (> 200 operations) | exclude / subsample / hard cap | Exp. 1 (compute) |
| D3 | Domain-restricted null model | what replaces the rejected domain labels? | Exp. 1 |

**On D2 — now the sharpest of the three.** Pairwise similarity is O(n²). The
corpus holds 77,611,030 operation pairs, of which **65,225,331 — 84.0% of all
computation — come from a single service** (Microsoft Graph, 11,422 operations).
The 70 services with more than 200 operations (3.2% of the corpus) hold **97.6%**
of all pairs. Any pair-weighted corpus statistic is therefore a statement about
a handful of mega-specs until D2 caps them. An ILSC score for a service that size
is also not interpretable. Some cap is required.

**On D3 — raised by this work, not yet in the proposal.** D-05 replaced domain
labels with provider proximity for the *perturbation control*, which resolves
Exp. 2. But Sec. 6 also specifies a **domain-restricted null model**, and that
still has no label source now that D-03 has rejected keyword labelling and D-04
has rejected LLM labelling. Provider-restricted is the obvious candidate. It
needs deciding before the Exp. 1 run, not during it.

  `api-spec/carts.json`. This is not a typo.
