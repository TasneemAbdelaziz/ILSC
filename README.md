# ILSC — Interface-Level Semantic Cohesion

Working repository for the ILSC metric. This package covers **Day 1–2 (dataset
curation)** plus the decisions that came out of it.

Anyone starting from this folder can rebuild the corpus in about 15 minutes.

---

## 1. What is here

```
src/
  filter.py            Corpus filtering pipeline (Sec. 7 of the proposal)
  domain_label.py      Keyword domain labeller — REJECTED, kept for the record
results/
  manifest.csv         1,831 surviving services with metadata
  manifest_labelled.csv  Same, plus (rejected) domain labels and evidence
  filter_log.csv       Every removed spec with its reason (2,307 rows)
  domain_validation_BLIND.csv   50-service manual validation sheet
  domain_validation_KEY.csv     Automatic labels for the same 50
specs/
  benchmarks/          Sock Shop OpenAPI specs (5 services, 28 operations)
docs/
  DECISIONS.md         Why each methodological choice was made
```

The 1,831 filtered specs themselves (464 MB) are **not** included — they are
regenerated by running the pipeline against the pinned commit below.

## 2. Reproducing the corpus

```bash
# 1. Dependencies
pip install pyyaml openapi-spec-validator

# 2. Fetch the source corpus at the pinned commit
git clone --depth 1 --filter=blob:none --sparse \
    https://github.com/APIs-guru/openapi-directory.git
cd openapi-directory
git sparse-checkout set APIs
git checkout f04b8d0bcd39c52e1cf3ad7a5fe744709832ae49
cd ..

# 3. Run the pipeline
python src/filter.py openapi-directory/APIs
```

**Pinned commit:** `f04b8d0bcd39c52e1cf3ad7a5fe744709832ae49`
Without pinning, the corpus changes under you and no result is reproducible.

Runtime is roughly 5 minutes with libyaml installed (`yaml.CSafeLoader`), and
about ten times longer without it. Check with:

```python
import yaml; print(hasattr(yaml, "CSafeLoader"))
```

## 4. Open decisions

These are unresolved and block later steps:

| # | Decision | Options | Blocks |
|---|---|---|---|
| D1 | Provider cap | none / 50 / 30 / 20 per provider | Exp. 1 |
| D2 | Oversized services (> 200 operations) | exclude / subsample / hard cap | Exp. 1 (compute) |

**On D2.** Pairwise similarity is O(n²). The corpus contains 328,369,848
operation pairs in total, of which 249,995,980 — 76% of all computation — come
from a *single* service (Microsoft Graph OData, 22,361 operations). An ILSC
score for a service that size is also not interpretable. Some cap is required.

## 5. Benchmark specs

`specs/benchmarks/` holds the five Sock Shop services used for the
code-correlation study.

| Service | Operations | Pairs |
|---|---|---|
| user | 15 | 105 |
| carts | 5 | 10 |
| catalogue | 4 | 6 |
| orders | 2 | 1 |
| payment | 2 (1 after `/health`) | 1 |
| **Total** | **28** | **123** |

Two things to remember:

- All five are **Swagger 2.0**, so they need conversion before parsing.
- Spec paths differ per service in the upstream repos: `apispec/user.json` but
  `api-spec/carts.json`. This is not a typo.

The `< 3 operations` corpus filter is **not** applied here — see DECISIONS.md.
