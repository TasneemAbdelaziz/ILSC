# Replication package — what has been tested, and what has not

*Proposal Sec. 11, Days 13–15: "Test the package on a fresh clone — if it doesn't
run for you, it won't run for reviewers."*

This file exists so the claim "it reproduces" is bounded rather than asserted.

---

## What was tested — a fresh clone, 2026-09-08

`git clone` into an empty directory, then:

| Check | Result |
|---|---|
| Every script `run_all.py` invokes exists in the committed tree | **22 of 22** |
| Every module in `src/` imports with **no corpus present** | **24 of 24** |
| Unit tests run from the clean tree | **17 of 17 pass** |
| `src/convert.js` committed and its Node dependency declared in `package.json` | ✅ |
| Regenerable artifacts correctly *absent* (`specs/clean*`, `parsed*`, `.cache/`) | ✅ |
| Committed artifacts present (`results/`, `figures/`, `specs/benchmarks/`) | ✅ |

That the modules import with no corpus present matters more than it looks: it
means a reviewer who clones the repository can read, lint and unit-test the
metric **before** committing to a 25-minute corpus fetch, and that no module
does data loading at import time.

## What was NOT tested, stated plainly

**The end-to-end data run has not been executed from a fresh clone.** Doing so
requires re-fetching both pinned corpora — 6,757 specification files across two
repositories — and re-running every step, roughly an hour of wall time plus the
embedding pass. The pipeline has only ever been run in place, in the working
tree where it was developed.

This is the difference between *"the package is complete and importable"* and
*"the package reproduces the numbers"*. Only the first is established. The
second is a real remaining task and it is the one the proposal actually asks
for, because the failure mode it is designed to catch — a step that silently
depends on a file left over from development — is invisible to a structural
check.

**Two further gaps in reproducibility, both already recorded:**

- `src/entity_extract.py` needs a **FudanSELab/train-ticket checkout**, which
  this repository does not vendor and `run_all.py` therefore does not invoke.
  The commented block at the foot of `run_all.py` says so rather than leaving
  the omission silent. `results/endpoint_entities_trainticket.csv` is committed,
  so Exp. 3 reproduces without it.
- `results/endpoint_entities.csv` (Sock Shop) is a **manual artifact**. It is
  committed and is not regenerated by any script; every row carries a
  `file:line` reference so any claim in it can be checked against the source.

## How to run it

```bash
pip install -r requirements.txt
npm install                       # swagger2openapi 7.0.8, one step only

git clone --filter=blob:none --sparse \
    https://github.com/restful-ma/thresholds.git rama-thresholds
cd rama-thresholds && git sparse-checkout set benchmark-repository/openapi \
  && git checkout 5b0b2a3322d3b2b7c0e0f2c0c0ad0e524e67bf82 && cd ..

git clone --filter=blob:none --sparse \
    https://github.com/APIs-guru/openapi-directory.git openapi-directory
cd openapi-directory && git sparse-checkout set APIs \
  && git checkout f04b8d0bcd39c52e1cf3ad7a5fe744709832ae49 && cd ..

python run_all.py
```

**Everything is pinned:** `SEED = 42`, both corpus commits, `all-MiniLM-L6-v2`
as the embedding model, `swagger2openapi@7.0.8`, and Python dependencies in
`requirements.txt` — including the four metric-track packages (`numpy`, `scipy`,
`sentence-transformers`, `torch`) that were **in use but unpinned** until this
was written. Without those pins a fresh clone could have installed a different
SBERT revision and produced different f1/f6 vectors from identical inputs.

**One environment dependency is not pinned and cannot easily be:** the SBERT
model weights are fetched from Hugging Face by name. The name is pinned in
`config.EMBEDDING_MODEL`; the upstream artifact is trusted to be immutable.

## Figures

All eight figures share one palette and one set of rcParams, defined in
[`src/figstyle.py`](../src/figstyle.py) and applied by every figure-producing
script. Vector PDF throughout, with TrueType embedding (`pdf.fonttype = 42`)
rather than Type 3, which journals ask for.

The categorical slots are validated as a set rather than chosen by eye: worst
pair CVD ΔE 9.2 (deuteranopia), normal-vision ΔE 27.6. One slot sits below the
3:1 contrast target against the light surface, so every figure carries the
required relief — a legend whenever there are two or more series, a distinct
marker shape per series, and the underlying CSV in `results/` as the table view.

**Fig 6 was rebuilt, not merely recoloured.** It plotted edge density and
component count on a twin axis. Two measures on two y-scales let whoever draws
the chart decide where the curves cross, which is the most misleading thing a
chart can do; it is now two stacked panels sharing one x-axis.
